# 自懂填 Auto-Fit — 需求摘要

來源：`需求及資訊來源/`（設計階段.md、V1.0 安裝包、網頁板型設計想法.pptx、來源資料夾範例）

## 1. 現況（V1.0，tkinter 桌面版）
- 流程：選資料夾 → 輸入民國日期 → 產生 Word。
- 靠**檔名**帶資料：`內容說明-設計-實際.jpg`（例 `4F帷幕骨架安裝間距尺寸檢查(1)-700mm±10-700mm.jpg`）；不符格式者略過（例 `203662_0.jpg`）。
- 輸出：A4、每頁 3 列 × 2 張、照片左下疊日期、下方「內容說明／設計／實際」標楷體 8pt，頁首「永青營造工程股份有限公司／施工自主檢查照片(檢查日期：民國)」。存於同資料夾，檔名 `民國日期 資料夾名.docx`。
- 核心可留用：`self_check_core.py`（排版、日期戳、docx 產出）。

## 2. 痛點 → 要解決
| 痛點 | 新版做法 |
|---|---|
| 照片一張張貼、排版、調大小 | 沿用核心自動排版 |
| 回辦公室要依設計值分類 | 依資料夾分類 + 拖曳調整順序/搬移資料夾 |
| 在 docx 裡一張張看照片填三欄 | AI 辨識白板手寫 → 自動填「內容說明／設計／實際」，人工校對 |

## 3. 需求
1. **機密**：盡量本地運算；照片不上傳伺服器（若接 LLM API 屬例外，需明確讓使用者選擇）。
2. AI：Hugging Face 開源視覺模型（本地）或大語言模型 API，二者皆待實驗驗證。
3. 硬體：i5-10400 / 16G DDR4 辦公電腦要跑得動。
4. **網頁介面**：處理照片資料夾，依資料夾分類，拖曳照片改順序或搬移資料夾。

## 4. 白板辨識策略（設計階段.md 結論）
- 兩階段：低解析度（512–768px）整圖先定位白板 → 從原圖裁切白板區域再送辨識。
- 全圖壓 1500px 仍清楚；1024px 小字開始糊；768px 以下風險高。
- 成本粗估每張 NT$0.02–0.15，非主要考量。
- 白板欄位（範例照片）：檢驗項目、標準值（=設計）、實際值、查驗位置、查驗日期。

> 版型：已定案（2026-09-04）——拖入的 docx 會整份解析出版面（頁面、抬頭、格線、說明欄位、日期戳），見 `版型.md`。

## 5. 介面（已定案 2026-09-02：B+E 混合，見 `介面規格.md`）
pptx 原始想法：
- **入口頁**：選資料夾（點選或拖放）、板型選擇（點選或拖放 doc/docx）、簡短提示詞（描述「照片內容／設計值／實際值」在白板上的位置，沒填用預設）。
- **給路徑之後**：左側資料夾樹（根 → 4F\ → 5F\），每張照片一列：拖曳把手 + 縮圖 + 「內容說明／設計／實際」三欄可編輯。

## 6. 來源資料夾範例
```
帷幕骨架/
  4F/  3 張已依檔名命名（+ 1 個 ~$ 暫存檔要忽略）
  5F/  3 張原始檔名 203662_0.jpg…（+ Thumbs.db 要忽略）
```
→ 介面需同時處理「已命名」與「未命名」照片；已命名者可直接解析檔名預填三欄。
