# 放到辦公室內網給同事測試

`tools/dev_server.py --lan` 把 `web/` 綁在 `0.0.0.0:8765`，同一區網的同事用
`http://<你的IP>:8765/` 就能開。照片一樣只在**同事自己的**瀏覽器裡處理，不會傳到你這台。

## 為什麼同事的 Chrome 要設一次旗標

網頁靠 File System Access API（`showDirectoryPicker`）讀寫資料夾，瀏覽器只在
**安全內容環境**（secure context）才給用 —— 也就是 `localhost` 或 HTTPS。
`http://192.168.x.x:8765` 兩個都不是，所以不設定的話網頁會退成「唯讀複本」：
可以校對、下載 Word，但拖曳搬移、刪到 `_回收桶`、直接寫回資料夾都不會動到檔案。

`chrome://flags/#unsafely-treat-insecure-origin-as-secure` 就是叫 Chrome
「把這個網址當成安全來源」。只填自己內網那一個網址，別填公開網站。

## 你這台（開站的人）

1. 確認 IP：命令提示字元 `ipconfig`，看「IPv4 位址」（通常 `192.168.` 或 `10.` 開頭）。
2. 開防火牆（**以系統管理員身分**開命令提示字元，只做一次）：

   ```
   netsh advfirewall firewall add rule name="AutoFit LAN 8765" dir=in action=allow protocol=TCP localport=8765 profile=private
   ```

   不想留規則時：`netsh advfirewall firewall delete rule name="AutoFit LAN 8765"`
3. 雙擊上一層的 `4_架設到內網.bat`。視窗會印出內網網址跟要給同事的設定步驟。
4. **視窗關掉就斷線**；你的電腦睡眠 / 關機同事也連不到。

IP 每次開機可能不一樣。改用電腦名稱比較穩：`http://j6030832:8765/`（同事那邊旗標就填這個）。

## 同事那台（每人做一次，約 1 分鐘）

1. 用 **Chrome 或 Edge**（Firefox 沒有這個 API，一定只能唯讀）。
2. 網址列輸入 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`
   （Edge 是 `edge://flags/#unsafely-treat-insecure-origin-as-secure`）。
3. 空格貼上你給的網址，例如 `http://192.168.1.23:8765`（**不要**加結尾斜線）。
4. 右邊下拉選 **Enabled** → 按右下角 **Relaunch**。
5. 開 `http://192.168.1.23:8765/`。入口頁**沒有**跳「這個瀏覽器不支援直接讀寫資料夾」
   就代表設定成功。

## 同事連不到（「回應時間過長」）怎麼查

旗標只影響能不能讀寫資料夾，**跟連不連得到無關**。「回應時間過長」是封包被丟掉，
照下面順序查，每一步都有明確的是/否：

**你這台**

1. 先確認 `3_開啟網頁(localhost).bat` 的視窗已經關掉。它綁 `127.0.0.1:8765`，
   跟 `4_架設到內網.bat` 搶同一個 port，Windows 的 SO_REUSEADDR 會讓兩個都「成功」，
   但連進來的封包不一定進到對的那個。**同時只留一個視窗。**
2. 確認真的在聽全部介面：

   ```
   netstat -ano | findstr :8765
   ```

   要看到 `0.0.0.0:8765 ... LISTENING`。看到 `127.0.0.1:8765` 就是開錯 bat。
3. 確認 192.168.1.95 是你「真正的」網卡：

   ```
   ipconfig | findstr IPv4
   ```

   如果列出好幾個，VMware / Hyper-V / WSL 的虛擬網卡也會有 IP，別給錯那個。
4. 確認網路類別 —— **這是最常見的原因**：

   ```
   powershell -Command "Get-NetConnectionProfile"
   ```

   會列出**每一張**網卡。要看的是「同事實際連的那個 IP」那一張（通常是`乙太網路`），
   不是 Tailscale / VMware / Hyper-V 那些虛擬網卡 —— 虛擬網卡常常是 `Private`，
   會讓人誤以為沒問題。那一張的 `NetworkCategory` 是 `Public` 的話，
   `profile=private` 的防火牆規則根本不會生效。

   重跑 `0_開通防火牆(只做一次).bat`，它會問你要不要改成所有設定檔都開，選 y。
   （或直接 `python tools\open_firewall.py --any-profile`，要系統管理員。）

**同事那台**

5. ```
   powershell -Command "Test-NetConnection 192.168.1.95 -Port 8765"
   ```

   - `PingSucceeded: False` 且 `TcpTestSucceeded: False` → 兩台根本不在同一個網段，
     或公司網路有客戶端隔離。先比對他 `ipconfig` 的 IPv4 是不是也 `192.168.1.` 開頭。
   - `PingSucceeded: True` 但 `TcpTestSucceeded: False` → 網路通、port 被擋，回到第 4 步。

**還是不行**

公司電腦若裝了防毒軟體自帶的防火牆（趨勢、賽門鐵克那類），`netsh` 改的是 Windows 防火牆，
擋人的是另一套，要在那套裡放行。這種情況通常得找 MIS。

## 之後要正式發布

專案設私人不開源，這點會決定發哪裡：

- **GitHub Pages**：免費方案的私有 repo 不能開 Pages（要 Pro/Team 以上）。
- **Cloudflare Pages**：私有 repo 也能發，跟施工儀錶板同一套。純前端沒有建置步驟，
  把 `web/` 當輸出目錄直接上傳即可。

## 跟施工儀錶板會不會打架

不會，兩邊沒有共用的東西：

| | 自懂填 | 施工儀錶板 |
| --- | --- | --- |
| 本機伺服器 | port 8765（只有跑 `.bat` 時才在） | 沒有；只是建置後推 Cloudflare |
| 設定檔 | `%USERPROFILE%\.autofit\` | `%USERPROFILE%\.dashboard\` |
| 排程 | 無 | 「施工儀錶板-建置發布」每 15 分鐘 |
| 防火牆 | 上面那條規則只開 TCP 8765 | 不受影響 |

要注意的只有一件事：兩邊上一層都有 `1_備份至Google雲端.bat`、`2_推至GitHub.bat`，
名字一樣，**別點錯資料夾**。
