# 版型（2026-09-04 完成）

拖入其他工程案的 docx → 解析成 LayoutSpec → 入口頁預覽校正 → 產出照那個版面的 Word。
不拖版型就用預設（＝V1.0 版面），行為與先前相同。介面其他部分見 `介面規格.md`。

## LayoutSpec（`web/js/template/spec.js`）

```
{ id, name, font,
  page:    { w, h, orient:'portrait'|'landscape', margin:{t,r,b,l} },   // twips
  heading: { place:'header'|'body', lines:[{text,sizePt,bold,align}] }, // text 裡的 {date} 換成檢查日期
  grid:    { perRow, blockRows, order:'row'|'col', seq, tableIndent },
  photo:   { h, maxW },                                                 // px：固定高度、太寬改以最大寬度為準
  caption: { sizePt },
  stamp:   { on, corner },
  block:   { cols:[dxa…],                                               // 一張照片佔的欄寬
             rows:[{ h, cells:[{ kind:'photo'|'text', col, colSpan, rowSpan,
                                 sizePt, align:'left'|'center'|'right', vAlign:'top'|'center'|'bottom',
                                 lines:[{ label, field } | { parts:[…] }] }] }] },
  unknown: [] }
```

- 整張表＝**區塊**（一張照片佔的格子）橫向重複 `perRow` 次、縱向排到照片用完。
- `field` ∈ `desc`｜`design`｜`actual`｜`seq`（流水號）｜`photoDate`｜`none`；`null` 代表還沒指定，`validateSpec` 會擋下來。
- **一行的內容一律看成「文字／欄位交錯的多段」**（`lineParts()`）：`{text}` 照原樣印、`{field}` 換成值、`{br:true}` 是段落內換行（`cellText` 給出 `\n`，`docx-export` 轉成 `<w:br/>`）。`{label, field}` 是「一段文字＋一個欄位」的簡寫；同一行要放兩個以上欄位（例：`內容說明，設計值，實際值` 用逗號隔開）才存成 `parts`，由 `makeLine()` 決定要存哪一種。空值照原樣留空，分隔的逗號不會自己消失。
- `order` `'row'`＝由左至右換行、`'col'`＝由上而下換欄；`seq` 是預覽頁拖曳交換後的實際填入順序。
- 每一格預設**垂直置中、文字靠左**（照手改的正確版；樣本 docx 文字格常是靠上，不照樣本）；`align`／`vAlign` 沒寫就是這個預設，要改在版型頁的格子上按右鍵。
- `cell.col` 是這格從區塊第幾欄開始——跨列合併（`rowSpan`）讓出來的位置要靠它標明。
- 預設 spec（`defaultSpec()`）＝ V1.0 版面。

## 解析（`template/` 三支各自獨立的模組）

- `unzip.js`：用瀏覽器內建 `DecompressionStream('deflate-raw')` 讀 ZIP，不外掛解壓函式庫。
- `xml.js`：極簡 XML 讀取器，Node 測試與瀏覽器跑同一份程式碼（不用 DOMParser）。
- `parse.js`：
  1. `sectPr` → `page`。
  2. 抬頭：主表格前的段落；沒有就讀預設 `headerReference` 的頁首。文字裡的日期換成 `{date}`。
  3. 主表格（含 `wp:inline` 的 `tbl`）：`gridCol` → 欄寬；有圖片的列＝照片列；`wp:extent` → 照片框；第一個照片列到下一個照片列之間＝一個區塊的列；`perRow`＝照片列的圖片數，`block.cols`＝總欄數 ÷ `perRow`，`blockRows`＝樣本裡的照片列數（假設樣本剛好一頁）。`vMerge` 換算成 `rowSpan`。
  4. 欄位名：「內容說明：值」同格 → 直接對應；只有欄位名（`說明：`、`照片編號`）→ 認領同列右邊、或下面幾列的第一個空值格；同一格連續的純值段落算同一個欄位。
  5. 日期戳：照片格裡的浮動文字方塊內容像日期 → `stamp.on`。
  6. **讀不出來的列進 `unknown`，不猜也不靜靜套預設值。**

驗收：`tests/js/template-parse.test.mjs` 對三份 fixture 解析出的 `unknown` 都要是空的。fixture 由 `tools/make_template_fixtures.py` 從原始 docx 抽出並匿名（案名、公司名、說明內容換成「範例…」），原始 docx 不進 git。

## 版型頁（`ui/template-page.js`）：先選版型，再調整

入口頁按「讀取版型」進來。從入口頁直接拖一份 docx 進版型框，會跳過第一步直接進調整頁。

**1. 選版型**：列出這台電腦存過的版型（使用／調整／刪除）與「預設版面（V1.0）」；下面是「點選或把 docx 拖到這裡」，讀完一份新的就進調整頁。

**2. 版型調整**（所見即所得）：

- 整頁畫出接近實際大小的版面：1440 twips = 1 吋 = 96px、字級 pt × 4/3 = px，照 `block.cols`／`block.rows` 排格子，再依 `perRow × blockRows` 鋪滿一頁。列高用 `minmax(原高, auto)`（Word 的 `trHeight` 本來就是「至少」）。頁面比視窗寬就整頁縮放顯示（只縮顯示，不動版型）。
- **抬頭與說明格就是頁面上的字，點下去直接打字**（逗號、頓號、單位都照打）；要填值的位置是一顆**欄位膠囊**（下拉可換欄位，選「（留空）」就移除，退格也能刪）。同一行可以有好幾顆膠囊，中間夾自己打的字。
- 鍵盤與 Word 一致：**Enter＝分段**（從游標切成上下兩行，游標跟到新的一段）、**Shift+Enter＝段落內換行**（輸出成 `<w:br/>`）；貼上只收純文字。
- **點格子的空白處也能打字**：格子比字高、或字被膠囊佔滿時點不到那一行，`mousedown` 會把游標接到垂直距離最近的一行後面。
- **說明欄位可以拖**：滑到某一行會出現拖曳把手與 ×——把手搬到別格或別的位置（放在行的上半／下半決定插在前面還是後面），× 刪掉。把手與 × 用絕對定位疊上去，不佔欄寬。
- **工具列的「拖到表格中新增選項」**：內容說明／設計值／實際值／照片編號／拍照日期／文字——拖到某一行的字裡面就插進那一行（位置照滑鼠落點的游標），拖到行與行之間、或格子的空白處就新增一行。
- **格子上按右鍵**（照片格也行）跳出小選單選這一格的對齊：水平 靠左／置中／靠右、垂直 靠上／置中／靠下（`setCellAlign`），預覽與輸出的 Word 都照它。
- 格子上的號碼＝填照順序，可拖曳交換（`swapSlots`）。工具列其餘只放結構性的：每列張數、每頁列數、照片框、填入順序、日期戳。
- `validateSpec` 有錯就紅框列出原因並停用「完成」。上面這排操作列捲動時固定在頂端。
- 「存成版型」把調好的存進版型庫；「完成，使用這個版型」也會先存一份（同名覆蓋、沿用 id）再套用，出去的版型一定在庫裡，資料夾記住的才是這一份。

## 版型庫（`template/library.js`）

`autofit:v1:templates` 存校正好的版型（同名覆蓋，存的是複本）；`autofit:v1:template-by-folder` 記住每個根資料夾上次用哪一份，選到資料夾時自動帶回。壞掉的 JSON 一律當空的。

## 產出（`docx-export.js`）

照 LayoutSpec 組表格：頁面（含橫式，docx 函式庫在 landscape 會自己對調長寬，所以餵轉正前的尺寸）、抬頭放頁首或內文（`place:'header'` 交給 Word 每頁重印；`place:'body'` 改成**一頁一張表、每張表前各印一次抬頭**，第 2 頁起用 `pageBreakBefore` 強制分頁——整份一張表只會在第一頁有抬頭，是 2026-09-04 修掉的 bug）、欄寬＝`block.cols × perRow`、`rowSpan`／`colSpan`、`{date}` 換成**該資料夾的**檢查日期、日期戳依 `stamp.on` 決定要不要烙進照片。一次讀取（一個工程案）只用一種版型，每個資料夾各出一份 docx、各自一個檢查日期（在表格的資料夾列上填）。

驗收：`tests/test_docx_export.py` 直接用解析 fixture 得到的 spec 產檔——a 版型要和 V1.0 的骨架一致，b 版型要是橫式、10 個 `w:tr`、有 `vMerge`、欄位名換成照片編號／拍照日期／圖片說明，c 版型的欄位名要照印在獨立格；另有抬頭的兩個測試：內文抬頭 3 頁都要有（3 張表、2 個 `pageBreakBefore`）、頁首抬頭維持整份一張表。

## 已知限制

- 只支援「照片格＋說明格」的表格式版型；其他結構會解析失敗並要求手動設定。
- 樣本 docx 是填好的成品，只取版面，內含的照片與文字一律丟掉。
- 解析樣本時沒讀 `<w:br/>`，樣本裡的段落內換行不會帶進版型（自己在調整頁按 Shift+Enter 補）。
- UI 沒有自動測試（專案沒有 DOM 測試環境），改到版型調整頁時要自己在瀏覽器實跑一輪。
- 「拍照日期」**不讀照片 EXIF**：版型有這一欄時，一律填**該資料夾的檢查日期**（表格資料夾列的日期格），寫法是 `115.6.14`（`rocDot()`，月日不補 0，照樣本檔）。
- 表格框線沿用 docx 函式庫預設，沒有從樣本讀。
