## 版面描述物件 LayoutSpec

```
{ id, name,
  page:    { w, h, orient, margin:{t,r,b,l} },              // twips
  heading: { place:'header'|'body', font, lines:[{text,sizePt,bold,align}] },
  grid:    { perRow, blocksPerPage, order:'row'|'col', seq:[…], cellW, photo:{w,h}, photoRowH },
  caption: { font, sizePt, rows:[{cells:[{kind:'label'|'value', text?, field?, w}]}] },
  stamp:   { on, corner, sizePt, format },
  borders: { … } }
```

- `field` ∈ `desc` | `design` | `actual` | `seq` | `photoDate` | `text` | `none`（欄位對應由使用者在預覽頁指定）。
- `order` `'row'`＝由左至右換行、`'col'`＝由上而下換欄；`seq` 是拖曳交換後的實際填入順序。
- 預設 spec ＝ V1.0 版面（現在 `docx-model.js` 的 `LAYOUT` 常數）。

## 解析 `web/js/template/parse.js`

0. 模組：`unzip.js`（用瀏覽器內建 `DecompressionStream('deflate-raw')` 解 ZIP，不外掛函式庫）、`xml.js`（極簡 XML 讀取器，Node 測試與瀏覽器同一份程式碼）、`parse.js`（推版面）。
1. unzip → `document.xml`、`word/_rels/document.xml.rels`、預設 `header*.xml`。
2. `sectPr` → `page`。
3. 抬頭：主表格前的段落；沒有就讀 `sectPr` 的 default `headerReference`。
4. 主表格（含 `wp:inline` 圖片的 `tbl`）：`gridCol` → 欄寬；有圖片的列＝照片列；`wp:extent` → 照片框；第一個照片列到下一個照片列之間＝一個區塊的列；`perRow`＝照片列的圖片數，`block.cols`＝總欄數 ÷ perRow，`blockRows`＝樣本裡的照片列數（假設樣本剛好一頁）。`vMerge` 換算成 `rowSpan`，被合併讓出的位置用 `cell.col` 標明。
   欄位名的判法：「內容說明：值」同格 → 直接對應；只有欄位名（`說明：`、`照片編號`）→ 認領同列右邊、或下面幾列的第一個空值格。同一格連續的純值段落算同一個欄位。
5. 日期戳：anchor 的 `wps` 文字方塊且內容像日期 → `stamp.on`，位置換算成角落。
6. **讀不出來的欄位標成 unknown，預覽頁紅字要求指定，不靜靜套預設值。**

驗收：`tests/js/template-parse.test.mjs` 對三份 fixture 解析出的 `unknown` 都要是空的。

## 預覽（入口頁選檔後立刻顯示，`web/js/ui/template-preview.js`）

- 左：依 spec 畫的頁面示意，格子標 1..N；切換橫向／直向填入順序，也可拖曳格子交換編號。
- 右：可改抬頭每行文字與字級（含 company／title）、每頁幾張、照片框、**欄位對應下拉**、**日期戳勾選**。
- 「存成版型」→ 版型庫（`autofit:v1:templates`），入口頁下拉可直接選用；同時記住每個資料夾上次用哪一份。

## 產出

`docx-model.js` / `docx-export.js` 改吃 LayoutSpec 而非寫死常數。一次讀取（一個工程案）只用一種版型，每個資料夾各出一份 docx 的規則不變。

## 已知限制

- 只支援「照片格＋說明格」的表格式版型；其他結構解析失敗會明講並要求手動設定。
- 樣本 docx 是填好的成品，只取版面，內含的照片與文字一律丟掉。
