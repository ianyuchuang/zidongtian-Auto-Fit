# 介面規格 — 定案 B+E 混合工作台（2026-09-04 更新）

視覺稿：`docs/ui-BE-mockup.png`；可編輯畫布在 Claude 專案「自檢表照片製作工具」的 Artifact「自懂填 Auto-Fit 介面板型」（第 2 頁為落選的 A–E）。
需求背景見 `docs/需求摘要.md`。

## 頁面
1. **入口頁**：只做兩件事——選資料夾（點選/拖放；選到後顯示資料夾名＋子資料夾摘要，瀏覽器拿不到完整磁碟路徑）、選版型（顯示目前用哪一份＋「已存的版型」下拉＋「讀取版型」，拖 docx 進來直接開版型調整頁）→「開始讀取」。畫面見 `入口頁.png`。
   - 上次開過的資料夾記在 IndexedDB，會出現「上次開的是 X ─ 接回這個資料夾／忘掉」；Chrome 要求使用者點一下才給權限。選到資料夾時，若這個資料夾上次用過某個版型會自動帶回。
   - 從工作台按「回首頁」回來時，資料夾、版型、辨識設定都留著。
   - 拖放：**整張入口頁都接得住**，拖進來的東西自己分是資料夾還是版型 docx（拖歪了也不會白忙）。頁面沒接住的拖放一律擋掉瀏覽器的預設行為，否則會跳去開檔案而變成空白頁（2026-09-04 的 bug）。
   - **檢查日期不在這裡**（改在工作台的資料夾列上填，每個資料夾各一個）；**辨識方式與提示詞也不在這裡**，見下面的「AI 辨識」。
1b. **版型頁**：入口頁按「讀取版型」進來——先「選版型」（存過的版型／預設版面／讀一份新的 docx，畫面見 `選版型頁.png`），讀了 docx 才進「版型調整」，整頁所見即所得地調版面（畫面見 `版型調整頁.png`），按「完成，使用這個版型」回入口頁。細節見 `版型.md`。
2. **工作台**（單頁三欄）
   - **頂列**：資料夾、版型兩個 pill（＋設定過辨識方式後多一個引擎 pill）；「🤖 AI 辨識」；「批次修改設計值」；「產生 Word 檔」。
   - **左欄 200px・資料夾樹**：根資料夾 + 子資料夾 + 張數（回收桶固定排同層最後）；「新增資料夾」；底部辨識進度／已確認／待校對／已刪除。
   - **中欄・可篩選表格**：篩選 chip（全部／檔名解析／AI 待校對／低信心）+ 搜尋（比對內容說明與檔名）。表格欄：拖曳把手｜縮圖｜內容說明｜設計｜實際｜信心｜狀態｜勾選，依資料夾分組（群組列的資料夾名旁（靠左）有該資料夾的「📅 檢查日期」輸入格，預設今天；群組列與表頭可全選）。欄寬固定（`table-layout: fixed`），換篩選、收合、換序都不會位移。三欄可直接在儲存格編輯，Tab／Enter 移動（勾選框不在 Tab 順序內）。勾選後上方工具列（永遠佔位，不會讓表格上下跳）：已勾選 N 張（其中 M 張目前被篩選隱藏）／搬到資料夾（下拉，不含回收桶）／刪除／取消勾選。
   - **右欄 380px・檢視器**（寬度＝CSS `--viewer-w`）：檔名 + 狀態；大圖（左下疊日期，載入失敗會顯示原因與「重試」）；白板裁切圖（用 AI 回傳的 bbox 四邊外擴 15% 裁出；框到整張或小得不像白板就不裁，改說明原因）；三欄（與表格同步）；「🗑／↩ 還原」「跳過」「確認，下一張（Enter）」；上一張／下一張。

## AI 辨識
- 讀取資料夾後**不會自動辨識**；檔名解析不出來的照片狀態是「待辨識」，不用 AI 也可以直接手打三欄。
- 頂列「🤖 AI 辨識」開對話框：辨識方式（模擬／本地模型／LLM API）、提示詞（留空用預設）、辨識範圍（尚未辨識的 N 張／目前勾選的 N 張／全部重新辨識，另有勾選項才會連「已確認」的一起重跑）。
- 選 LLM API 時：供應商（四家，附申請教學與申請頁）＋金鑰＋該家的額外欄位（Claude 公司帳號的 Workspace ID，選填）＋「測試連線」＋**型號下拉**。型號一律按「測試連線」時向該公司伺服器要回來（不寫死），能看圖的預設列出、其餘勾「連不能看圖的型號也列出來」才顯示；選過的型號記住，下次開直接帶回來。沒有型號不能開始辨識。細節見 `LLM-API.md`。
- 辨識期間跳出進度視窗（可「停止辨識」），**停在工作台不換頁**，表格與檢視器的欄位、篩選 chip、搜尋、勾選、頂列按鈕全部反灰鎖住。
- 保險：送出前先記下三欄與狀態，回來時若與當初不同（使用者自己改過／確認過）就只補 bbox 與信心，不覆蓋。

## 互動規則
- 表格列拖把手 → 改順序（＝Word 輸出順序）。
- 表格列拖到左樹某資料夾或群組列 → 實際搬移檔案到該資料夾。
- 拖的是勾選列 → 整批一起搬；一張失敗不影響其他張，結果彙整提示。
- 勾選會跨篩選累積（切 chip 再勾下一批也留著）；工具列會標「其中 N 張目前被篩選隱藏」，刪除確認框逐一列出檔名。
- **刪除＝搬進「照片所在資料夾」自己的 `_回收桶`**（沒有就自動建；網頁無法用 Windows 資源回收桶）。刪掉的照片**留在原資料夾群組的最後一列反灰顯示**：欄位鎖住、狀態「已刪除」、列上有「↩ 還原」搬回同一層。左樹以 🗑 顯示（排同層最後），統計與 chip 都不含已刪除，產生 Word 時略過。
- 點列 → 右欄顯示該張；右欄「確認」→ 狀態變「已確認」並跳下一張待校對（沒有下一張會提示）。
- 檢視器的大圖或白板裁切圖 → 點一下開燈箱（`js/ui/lightbox.js`）：滾輪以游標為錨點縮放 100%~800%、拖曳平移、雙擊還原、Esc／✕ 關閉。**燈箱只蓋住左欄與表格，右欄檢視器留著**，看放大的白板同時可以打三欄，← → 也照樣換照片；焦點在輸入格時 `+ - 0` 讓給打字。按「確認，下一張」或 ‹ › 換照片時，燈箱跟著換圖並把縮放歸零。
- 瀏覽器「上一頁」＝回首頁（工作台進場會 pushState），不會直接離開網站。
- 狀態：`待辨識`（尚未辨識，藍）、`檔名解析`（檔名符合「內容說明-設計-實際」格式，灰）、`AI 辨識・待校對`（黃，欄位虛線底色）、`AI 低信心・請確認`（紅）、`已確認`（綠）、`已刪除`（灰，反灰整列）。
- 信心欄：AI 結果顯示百分比；檔名解析顯示「—」。
- 低信心判定（`state.js`）：**先看欄位、再看信心**。欄位健全度 `fieldWarnings()` 有任何一項不過（三欄有空的、欄位裡是「無法辨識」之類的話、設計與實際的數字個數對不上）就直接算低信心；都過了才比模型自報信心，門檻 **85**；模型沒給信心也算低信心。理由：實測有模型三欄全錯卻自報 68%（`辨識實測-尺寸11F.md`）。欄位的毛病會顯示在右欄狀態下方。

## 資料流
掃描資料夾 → 每張照片：檔名可解析 → 直接預填；否則 → 待辨識，等使用者按「AI 辨識」→ 兩階段辨識（低解析定位白板 → 原圖裁切 → 辨識三欄 + 信心）→ 表格。
產生 Word 沿用 `self_check_core.py` 的排版（每頁 3 列 × 2 張、標楷體、日期戳），每個資料夾各一份。
